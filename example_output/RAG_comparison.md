# Порівняння підходів до побудови RAG

## 1. Naive RAG
**Опис:**
Naive RAG є базовою реалізацією, де система просто витягує релевантну інформацію з бази знань і передає її безпосередньо до моделі для генерування відповіді. Він складається з чотирьох основних етапів: 
- **Індексація:** Підготовка та організація даних.
- **Витягування:** Знаходження релевантних даних за запитом.
- **Доповнення:** Поєднання запиту з отриманими даними.
- **Генерація:** Вироблення відповіді на основі доповненого контексту.

**Переваги:**
- Простота реалізації.
- Підходить для простих запитів.

**Недоліки:**
- Обмеження у обробці складних запитів.
- Висока ймовірність генерації неправильних відповідей (глюки).

**Джерела:**
- [DevStark](https://www.devstark.com/blog/naive-rag-advanced-rag-and-modular-rag-architectures/)

## 2. Sentence-Window Retrieval
**Опис:**
Цей підхід є більш просунутим, оскільки зберігає структуровану інформацію у вигляді речень. Підхід передбачає:
- Розбивання документів на речення.
- Групування речень у чанк (фрагменти).
- Створення взаємозалежної бази даних, що зберігає зв'язки між чанками.

**Переваги:**
- Підвищена контекстуальність і когерентність у відповідях.
- Зменшення "галюцинацій" завдяки доступу до більшого контексту.

**Недоліки:**
- Більш складне управління та реалізація.
- Потребує більше ресурсів для обробки та зберігання.

**Джерела:**
- [Sentence Window Retrieval RAG Approach](https://aiengineering.academy/RAG/04_Sentence_Window_RAG/)

## 3. Parent-Child Retrieval
**Опис:**
Цей підхід передбачає витягування повних документів (батьківських) з яких витягуються конкретні уривки (дитячі). Це дозволяє моделі взаємодіяти з більшою кількістю контексту під час обробки запитів.
- Батьківські документи служать основною структурою, тоді як дитячі частини додають деталі.

**Переваги:**
- Підвищення точності та релевантності за рахунок зберігання більшого контексту.
- Краще управління складними запитами.

**Недоліки:**
- Складність реалізації та зберігання.
- Можливо, вища затрата часу на обробку порівняно з simpler approaches.

**Джерела:**
- Інформації з DZone не вдалося отримати, але можна звернутися до [LangChain's Parent Document Retriever](https://medium.com/data-science/langchains-parent-document-retriever-revisited-1fca8791f5a0) як альтернативи.

## Загальний Висновок
- **Naive RAG** підходить для простих випадків, де не потрібно глибоке розуміння контексту.
- **Sentence-Window Retrieval** забезпечує краще стратегічне зберігання контексту й підходить для завдань, що потребують глибшого аналізу тексту.
- **Parent-Child Retrieval** найбільш складний, але й найефективніший у роботі з комплексними запитами, з розширеним контекстом. 

Ці три підходи демонструють прогрес у побудові систем RAG, адаптуючи різні стратегії для покращення якості та точності AI-відповідей.
